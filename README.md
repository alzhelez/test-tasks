# Restful-Booker API — тестовое задание

Тестирование REST API сервиса **[Restful-Booker](https://restful-booker.herokuapp.com/)**
([документация](https://restful-booker.herokuapp.com/apidoc/index.html)).

## Покрытые эндпоинты

| Эндпоинт | Метод |
|---|---|
| `/auth` | POST |
| `/booking` | POST |
| `/booking` (фильтры `firstname`, `lastname`, `checkin`, `checkout`) | GET |
| `/booking/:id` | GET, PUT, PATCH, DELETE |
| `/ping` | GET |

## testcases/тест-кейсы.xlsx

Лист `Summary` — сводка по количеству кейсов. Далее — по одному листу на группу эндпоинтов:
`POST_auth`, `POST_booking`, `GET_booking_list`, `Booking_ID_CRUD`, `GET_ping`.

Колонки: `ID`, `Эндпоинт`, `Метод`, `Название теста`, `Тип` (Позитивный/Негативный),
`Приоритет`, `Предусловия`, `Шаги`, `Тестовые данные`, `Ожидаемый результат`, `Примечание`.

Итого: **66 тест-кейсов** (21 позитивный, 45 негативных), часть из них при исполнении на
реальном сервисе выявила отклонения от ожидаемого поведения — они помечены в колонке
«Примечание» ссылкой на соответствующий баг (`BUG-XX`) из баг-репорта.

## postman/restful-booker.postman_collection.json

- 5 папок по группам эндпоинтов, 46 запросов.
- Переменные коллекции: `baseUrl`, `token`, `bookingId`, `adminUser`, `adminPass`.
  `token` и `bookingId` заполняются автоматически скриптами в `Tests` после выполнения
  `AUTH-01` и `BOOK-C-01` соответственно — остальные запросы, требующие авторизации или
  id брони, используют эти переменные (`{{token}}`, `{{bookingId}}`).
- Каждый запрос содержит проверки (`pm.test`) во вкладке **Tests**, соответствующие
  ожидаемому результату из `тест-кейсы.xlsx`. 

## bugreport/баг-репорт.xlsx

9 задокументированных дефектов с разделами: ID, заголовок, эндпоинт, Severity/Priority,
шаги воспроизведения, тестовые данные, ожидаемый результат, фактический результат, статус,
примечание. Основные находки:

- **BUG-01** — `POST /auth` возвращает `200 OK` с `{"reason":"Bad credentials"}` вместо
  `401/400` при неверных учётных данных.
- **BUG-02** — `POST /booking` не валидирует обязательные поля (`firstname`, `lastname`,
  `bookingdates`).
- **BUG-03** — `POST /booking` принимает бронь, где `checkout` раньше `checkin`.
- **BUG-04** — `POST /booking` принимает отрицательный `totalprice`.
- **BUG-05** — `DELETE /booking/:id` возвращает `201 Created` вместо `200/204`.
- **BUG-06** — отсутствует rate limiting на `POST /auth` (риск brute-force).
- **BUG-07** — повторный `DELETE` уже удалённой брони возвращает `405` вместо `404`.
- **BUG-08** — `GET /ping` возвращает `201` вместо `200`.
- **BUG-09** — `PATCH /booking/:id` принимает пустое тело `{}` без ошибки валидации.

Полное описание каждого дефекта — в самом файле (лист `Bugs`).
